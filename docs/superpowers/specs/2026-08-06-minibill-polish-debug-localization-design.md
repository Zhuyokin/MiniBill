# MiniBill 分享、统计、开发工具与本地化设计

日期：2026-08-06
状态：已确认

## 1. 目标

本次改动解决四类现有问题，并补充 App 内语言切换：

1. 分享流程和分享图样式异常。
2. 统计总览配色偏离视觉规范，日净额柱状图在单条或少量数据时布局异常。
3. Debug 构建缺少批量样例数据工具。
4. 关于页与分享内容仍使用系统账本符号，没有使用 MiniBill 的真实品牌图标。
5. 用户需要在 App 内即时切换简体中文、繁体中文、英语、日语和韩语。

## 2. 已确认约束

- 分享按钮直接打开 iOS 系统分享面板，不保留自定义分享预览页面。
- 分享图片继续在本机由 SwiftUI `ImageRenderer` 生成，不包含备注。
- 开发工具只编译进 Xcode Debug 构建，Release/App Store 构建不可见且不可调用。
- 样例数据提供 30、100、500 三档，覆盖最近三个月。
- 重新生成样例时替换旧样例；删除样例不能删除用户手工录入的数据。
- 关于页、月度分享图、单笔分享图及系统分享预览统一使用 `BrandIcon`。
- App 内首次启动默认简体中文，可即时切换简体中文、繁体中文、英语、日语和韩语。
- iOS 桌面名称遵循系统对 `InfoPlist.strings` 的本地化选择：简体中文为“小微账单”，繁体中文为“小微帳單”，英语、日语和韩语为“MiniBill”。App 内语言切换不尝试修改桌面名称。
- 支持 iOS 17 及以上，不新增第三方依赖。

## 3. 根因与参考实现

### 3.1 分享

现有实现先把分享卡写入临时 PNG，再进入独立预览页，通过 `ShareLink<URL>` 打开系统面板。该流程同时维护预览缩放、文件生命周期和分享元数据，容易出现缩放比例、文件表现形式或临时文件失效等样式问题。

用户给出的参考文件 `IndicatorMapView.swift` 本身没有分享代码；同一参考工程的实际分享实现位于 `IndicatorDetailView.swift`，使用 `ImageRenderer` 生成内存图片并直接交给 `ShareLink<Image>`。MiniBill 采用这一流程，同时保留既有 900×1200、2 倍渲染和固定浅色主题的图片规范。

### 3.2 统计总览

现有日净额图使用一个平均分配全部可用宽度的 `HStack`。因此只有一条或少量数据时，每根柱会被拉伸到整个卡片宽度；所有柱也从同一底部向上生长，没有以零轴区分正负方向。

统计页面将恢复既有视觉规范中的明确层级：浅色模式使用 `#F5F5F5` 页面背景、`#FFFFFF` 卡片、`#191919` 主文字、`#858585` 次要文字、`#07C160` 收入色。深色模式使用等价动态色，继续保持收入与支出的语义，并且不以颜色作为唯一信息载体。

### 3.3 品牌图标

资产目录已经包含 `BrandIcon`，启动页也已正确使用。关于页和两种分享卡仍硬编码 `book.closed.fill`，导致品牌表现不一致。新增一个统一品牌图标组件，集中处理图片缩放、圆角和可访问性。

## 4. 架构设计

### 4.1 分享边界

`ShareImageService` 负责把 `ShareCardPayload` 渲染为 `UIImage` 或 SwiftUI `Image`，不再创建临时文件。统计页与流水详情页负责创建稳定的分享载荷，并通过 `ShareLink` 直接呈现系统面板。

分享卡是纯展示视图：

- `MonthlyShareCard` 展示月份、净收益、收入、支出、笔数、日趋势与收入/支出 TOP 1。
- `EntryShareCard` 展示类型、项目名称、金额和发生时间。
- 两者均使用固定浅色画布、真实 `BrandIcon`，并明确排除备注。

不再保留 `SharePreviewView`。分享图生成失败时，页面显示本地化错误和重试入口，不创建空图片，也不打开无内容的系统面板。

### 4.2 统计图表边界

`DailyNetChart` 改用系统 Swift Charts：

- 横轴范围固定为所选月份的起止日期，而不是仅由已有数据点决定。
- `BarMark` 使用固定的合理柱宽，单条数据不会横向撑满卡片。
- 正值从零轴向上，负值从零轴向下。
- 纵轴使用包含零点的对称范围，使正负变化可比较；全零数据提供最小安全范围。
- 横轴只显示少量日期刻度，柱体仍按真实日期定位。
- 点击或选择有数据的柱体继续导航到当天流水。
- 空月份保留明确的空状态，不绘制误导性的零柱。

月份区间、对称纵轴和安全数值转换放入可单元测试的纯逻辑类型；SwiftUI 视图只负责绘制和导航。

### 4.3 Debug 样例数据边界

新增 Debug 专用样例数据工厂，整个实现和设置入口均置于 `#if DEBUG` 条件中。

工厂接收数量、参考日期和日历，确定性地产生 `LedgerRecord`：

- 数量只允许 30、100、500。
- 日期分布在参考日期向前的最近三个月。
- 同时包含收入、支出、多个项目、不同金额和部分备注。
- 所有金额满足现有输入上限并大于零。
- UUID 使用 MiniBill 样例数据的固定命名空间与序号，可以跨启动识别，而不需要修改正式 SwiftData 模型。

设置页 Debug 分组提供数量选择、生成/替换和删除操作。生成时先删除可识别的旧样例，再插入新样例并保存；任何保存失败都回滚整个上下文。删除只匹配样例 UUID，不基于项目名、备注或日期判断，因此不会误删正常账目。

### 4.4 品牌图标边界

新增 `AppBrandIcon` 视图，读取 `Image("BrandIcon")`，根据调用场景配置尺寸和圆角。以下位置统一使用该组件或同一资源：

- 关于 MiniBill 页面。
- 月度分享图品牌头。
- 单笔分享图品牌头。
- 系统分享预览图片。

桌面 App Icon 继续由 `AppIcon.appiconset` 管理，不在运行时切换图稿。

### 4.5 App 内语言边界

新增 `AppLanguage` 枚举和持久化语言状态，支持：

- `zh-Hans`：简体中文，首次启动默认值。
- `zh-Hant`：繁体中文。
- `en`：英语。
- `ja`：日语。
- `ko`：韩语。

根视图将所选语言对应的 `Locale` 注入 SwiftUI 环境，使 `Text`、`Label`、导航标题和日期/金额格式立即更新。对于错误消息、通知正文、分享图等不完全依赖 SwiftUI 环境的场景，使用统一的显式语言本地化函数，避免同一页面混用系统语言和 App 内语言。

切换语言时：

1. 持久化新的语言代码。
2. 更新根视图 `Locale`，立即重绘可见界面。
3. 重新协调已启用的本地提醒，使未来通知使用新语言。
4. 不修改 `AppleLanguages`，不强制退出 App，也不使用非公开 API。

设置页语言项改为 App 内选择器，不再跳转系统设置。现有 String Catalog 保留五语并补齐新增文案。`InfoPlist.strings` 继续决定 iOS 桌面名称，与 App 内语言状态彼此独立。

## 5. 用户流程

### 5.1 分享

1. 用户在统计页或流水详情页点击分享。
2. App 使用当前载荷和当前 App 内语言渲染 900×1200 图片。
3. iOS 系统分享面板直接出现，并显示该图片预览。
4. 用户完成或取消分享后仍停留在原页面。

### 5.2 样例数据

1. Debug 构建中，用户进入“我的”的“开发工具”。
2. 选择 30、100 或 500 条。
3. 点击生成并确认替换旧样例数据。
4. 保存成功后，账单首页和统计立即由 SwiftData 查询刷新。
5. 点击删除样例数据时，仅移除带样例 UUID 的记录。

### 5.3 语言

1. 用户进入“我的”并打开语言选择。
2. 选择五种语言之一。
3. 当前页面和整个导航层级即时使用所选语言。
4. 重新排程已启用的提醒；桌面名称仍由 iOS 系统语言选择。

## 6. 错误处理与数据安全

- 图片渲染失败：不分享空图片，展示本地化错误并允许重试。
- 样例生成失败：回滚 SwiftData 上下文，保留原有用户账目与旧样例状态。
- 样例删除失败：回滚上下文并显示错误，不报告假成功。
- 不支持的样例数量：工厂拒绝生成，不写入数据。
- 语言代码损坏或来自旧版本：回退到简体中文。
- 通知重排程失败：保留语言选择和提醒偏好，在设置页显示现有的可重试提示。
- 所有分享和样例数据操作均为本地操作，不增加网络、账号、分析或云同步。

## 7. 测试与验证

### 7.1 单元测试

- 图表月份范围覆盖月初至下月月初。
- 图表纵轴对单条正值、单条负值、正负混合、全零和极端 `Int64` 值生成安全范围。
- 样例工厂对 30、100、500 三档生成准确数量和唯一 UUID。
- 样例日期均落在最近三个月，且同时包含收入、支出和多个项目。
- 样例识别只匹配固定命名空间 UUID。
- `AppLanguage` 对五个语言代码正确往返，未知值回退简体中文。
- 显式本地化函数在五种语言下返回对应文本。
- 分享载荷继续排除备注。

### 7.2 构建与人工验证

- 运行全部 Swift Package 测试。
- 构建 iOS Debug 模拟器目标。
- 构建 iOS Release 模拟器目标，并检查开发工具代码和入口不可用。
- 在空数据、单条、少量、正负混合数据下检查统计图布局与点击导航。
- 分别从统计页和流水详情页验证系统分享面板、图片比例、品牌图标和隐私字段。
- 依次切换五种语言，检查当前界面、分享图、错误文案与通知排程。
- 检查中文系统桌面名称为“小微账单”或“小微帳單”，其他已支持系统语言显示“MiniBill”。
- 检查浅色和深色模式的页面背景、卡片、文字与收入/支出语义。

## 8. 非目标

- 不增加自定义主题或颜色选择器。
- 不恢复自定义分享预览页。
- 不把开发工具编译进 Release。
- 不增加服务器、云同步、遥测或第三方图表依赖。
- 不通过非公开 API 或修改 `AppleLanguages` 强制改变系统桌面名称。
- 不改变备份格式；Debug 样例若被用户主动导出，将按普通账目写入备份。
