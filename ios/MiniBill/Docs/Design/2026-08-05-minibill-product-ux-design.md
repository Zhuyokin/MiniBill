# MiniBill MVP 产品与交互设计规范

日期：2026-08-05  
状态：待最终书面审核  
平台：iPhone / iPad，iOS 17+

## 1. 产品定义

MiniBill 是面向摆摊、零工、副业和小微个体经营者的本地离线现金流水工具。它不要求用户理解会计、分类体系或账户体系，只回答三个问题：

1. 今天收了多少、花了多少？
2. 这个月赚了多少？
3. 哪些项目贡献了收入或支出？

核心承诺：无注册、无网络依赖、三秒记一笔、数据由用户掌控。

## 2. 目标用户与高频任务

典型用户：夜市摊主、跑腿或配送兼职、手工制作者、自由职业者、短期零工和副业经营者。

高频任务按优先级排序：

| 优先级 | 任务 | 成功标准 |
|---|---|---|
| P0 | 记一笔收入或支出 | 金额输入后只需点选项目候选并保存；无需选分类 |
| P0 | 看今日流水 | 打开 App 即可看到，按日期分组 |
| P0 | 看本月收入、支出和净收益 | 首页首屏可见 |
| P0 | 修改或删除错误流水 | 从流水行一步进入详情 |
| P0 | 按项目名称看收入、支出排行 | 首页汇总卡进入统计页 |
| P0 | 手动导出与恢复备份 | 无网络可完成，恢复前可预览 |
| P0 | 每日与月末提醒 | 用户主动开启后由 iOS 本地排程 |
| P1 | 分享月度收益图 | 本机生成，不包含备注 |
| P1 | 分享单笔流水图 | 本机生成，仅展示当前一笔 |
| P1 | 五语与系统地区格式 | 简中、繁中、英、日、韩 |

## 3. 设计原则

### 3.1 只展示当前任务需要的信息

- 首页只展示本月汇总、按日流水和“记一笔”。
- 日期和备注是可选字段，折叠在“备注与日期”中。
- 统计不是独立页签，通过本月汇总卡进入。
- 设置页不放分类、账户、主题和高级报表。

### 3.2 不要求用户维护业务字典

- 不存在分类模型、分类入口或分类 CRUD。
- 项目名称写在流水上，例如“冰粉”“摊位费”“跑腿收入”。
- 历史候选从既有流水推导，删除最后一笔相关流水后候选自然消失。
- 修改流水项目名称后，候选和统计自动变化。

### 3.3 离线能力必须是真离线

- 创建、查询、统计、分享、通知排程、备份编码和恢复均在本机完成。
- 不把“系统文件面板可选择 iCloud Drive”描述为 App 云同步。
- 不申请后台模式来伪装持续运行。

## 4. 信息架构

底部只保留两个页签：

- `账单`：本月汇总、今日/历史流水、快速记账。
- `我的`：提醒、备份恢复、语言、隐私与关于。

二级页面：

- `统计`：从首页本月汇总卡进入。
- `流水详情`：从任意流水行进入，可编辑、删除、分享。
- `分享预览`：从统计页或流水详情进入。
- `提醒设置`、`恢复预览`、`隐私说明`、`关于 MiniBill`。

## 5. 页面设计

### 5.1 账单首页

首屏顺序：

1. 导航标题 `MiniBill`。
2. 本月汇总卡：月份、净收益、收入、支出、统计入口。
3. 今日流水，随后按日期倒序显示历史流水。
4. 右下角绿色悬浮“＋”。
5. 底部 `账单 / 我的` 双页签。

流水行内容：项目名称、时间、可选备注摘要、带正负号的金额。收入使用品牌绿；支出使用中性深色。收入与支出不能只靠颜色区分。

空状态：显示“还没有流水”，主操作仍是“记一笔”；不展示插画或教程轮播。

### 5.2 记一笔

点击“＋”后，从底部展开约四分之三屏的快速面板，保留首页上下文。

核心字段：

- 收入 / 支出切换。
- 金额。
- 项目名称。

交互顺序：

1. 面板打开后金额键盘可立即输入。
2. 默认选中收入；用户可切换支出。
3. 项目名称下显示最近使用候选，优先按最近使用排序。
4. 点选候选或输入新名称。
5. 点击“保存”，面板收起，新流水插入首页对应日期顶部。

项目名称是必填字段。金额必须大于零，最多两位小数。金额和项目名称是唯二核心信息；日期默认当前时间，备注默认空。

### 5.3 流水详情

支持修改类型、金额、项目名称、日期和备注。删除为红色低频操作，需要确认；确认文案明确“删除后统计会同步变化”。

支持分享当前流水。单笔分享图展示：MiniBill、收入/支出、项目名称、金额、日期时间；永不展示备注。

### 5.4 统计

统计页按选定月份展示：

- 净收益、收入、支出、流水笔数。
- 每日净收益柱形趋势。
- 收入项目排行。
- 支出项目排行。

项目聚合规则：去除首尾空格、将连续空格合并为一个、英文比较忽略大小写；除此以外使用精确匹配，不做模糊合并。原始项目名称仍按用户输入展示。

点击趋势柱进入当天流水；点击排行项进入该月份和该项目的流水筛选结果。

### 5.5 分享

月度分享图采用 3:4 竖版，逻辑画布 900×1200，导出倍率 2x。包含：品牌、月份、净收益、收入、支出、笔数、简化趋势、收入/支出 TOP 1。

单笔分享图包含：品牌、类型、项目名称、金额、日期时间。

隐私规则：

- 不分享备注、其他流水、备份状态或设备信息。
- 生成过程只使用本地 SwiftUI 视图和 `ImageRenderer`。
- 用户在预览后才进入系统分享面板。

### 5.6 我的

设置项固定为：

- 每日记账提醒。
- 月末结账提醒。
- 导出备份。
- 从备份恢复。
- 语言：跟随系统或 iOS 系统级 App 语言。
- 隐私说明。
- 关于 MiniBill。

不增加分类、项目管理、账户、主题切换和数据看板入口。

## 6. 通知设计

- 每日提醒默认建议时间 20:00。
- 月末提醒默认建议时间 21:00。
- 用户首次开启任一提醒时才请求系统权限。
- 权限被拒绝时保留 App 内偏好，显示“系统通知已关闭”，唯一操作为“前往系统设置”。
- 每日通知点击后进入快速记账；月末通知点击后进入当月统计。
- 通知标题和正文不含金额、项目名称或结余。

“月末结账”只表示核对本月收支，不创建结账单、不锁定月份。

## 7. 备份与恢复体验

导出生成单个 `.minibill` 文件。用户取消系统文件面板属于正常取消，不显示错误。

恢复流程：

1. 选择 `.minibill` 文件。
2. 在不修改本机数据的前提下解析和校验。
3. 展示备份时间、记录数、最早/最晚日期和本机记录数。
4. 提供“先导出当前账本”。
5. 红色操作“替换并恢复”完整替换本机流水。

MVP 不做合并、去重规则和部分导入。任何校验或写入失败都必须保持原账本不变。

## 8. 多语言与地区

支持：`zh-Hans`、`zh-Hant`、`en`、`ja`、`ko`。

- 品牌 `MiniBill`、备份键、枚举值和文件扩展名不翻译。
- 项目名称属于用户数据，不翻译。
- 日期、时间、数字和 CNY 金额按系统地区格式显示。
- 使用 String Catalog 管理界面、通知、分享图和错误文案。
- 繁中术语需要人工复核，不采用纯机械字形转换。
- 英文、日文和韩文按最长文案验证布局。

## 9. 可访问性与输入

- 支持动态字体；关键操作在最大辅助字号下不被截断。
- 金额和趋势使用文字、正负号与形状共同表达，不只使用颜色。
- 所有按钮、流水行和图表可点击项提供 VoiceOver 标签。
- 点击区域至少 44×44 pt。
- 支持 Reduce Motion；面板可采用淡入和短距离位移动画。
- iPad 维持单列阅读宽度，不扩成复杂多栏后台。

## 10. 失败状态

统一错误表达顺序：发生了什么、数据是否改变、下一步做什么。

| 场景 | 用户状态 | 数据保证 |
|---|---|---|
| SwiftData 无法打开 | 全屏“账本暂时无法打开”，提供重试 | 不静默创建空账本，不删除原存储 |
| 保存流水失败 | 面板保留输入并提示重试 | 不出现假成功流水 |
| 通知权限关闭 | 设置页内联提示并提供系统设置入口 | 账目不受影响 |
| 导出失败 | 提示更换位置或重试 | 本机账本不变 |
| 备份损坏或版本过新 | 恢复预览显示明确原因 | 写入前拒绝 |
| 恢复事务失败 | “恢复失败，原有记录未改变” | 整体回滚 |
| 项目候选推导失败 | 候选暂为空 | 用户仍可手工输入和保存 |

## 11. MVP 明确排除

- 分类与分类 CRUD。
- 客户、供应商、库存、欠款与应收应付。
- 预算、账户余额、发票、OCR、自动导入和银行同步。
- 多币种、汇率换算、多账本和多人协作。
- 登录、服务器、统计遥测和广告 SDK。
- “今天未记账才通知”等需要后台判断的条件提醒。

## 12. 验收摘要

- 常用项目可在三次主要点击内完成记账。
- 无网络、App 被结束后，已排程的本地通知仍由系统处理。
- 首页、统计、分享和备份均不依赖分类模型。
- 导出再恢复后，金额、项目名称、日期、UUID 和备注无损往返。
- 五种语言无开发 key 泄露、关键按钮截断或硬编码日期格式。
- 分享图不包含备注；备份恢复失败不改变原数据。
